Rehoboth Mezmur Privacy Terms Source

Privacy Policy

Effective date: November 4, 2026

This policy describes the current owner-operated Rehoboth Mezmur application maintained in the Protestant-Mezmur repository. It uses YouTube API Services to publish videos at the channel owner's request; it is not a public multi-user account service.

Information accessed

  • OAuth client credentials, refresh tokens and temporary access tokens supplied by the operator for Google authorization. The app does not request or store a Google password.
  • The authorized YouTube channel ID and channel information needed to check that uploads target the intended channel.
  • Video IDs, titles, descriptions, tags, visibility and publication status for videos uploaded or recovered through this workflow, plus caption track IDs, language, names and processing status needed for subtitle upload and retry reconciliation.
  • Operator-selected audio, images, lyrics, generated videos, thumbnails and upload metadata. Inputs may come from Telegram, local files and the project's configured public-source searches.

Purpose and permissions

Google authorization is used to confirm channel ownership, upload generated videos, thumbnails and timed Amharic lyric captions, set metadata, schedule publication and avoid duplicate uploads. The configured YouTube permission can manage video data and captions; the current uploader does not automatically delete existing videos or caption tracks.

Uploaded videos initially remain private. The workflow saves a randomized batch order and schedules public publication at four-hour intervals, appending to the channel's existing recorded future slots. The owner can change or cancel publication in YouTube Studio. The app is not affiliated with Google or YouTube.

Storage and public-repository disclosure

In GitHub Actions, Google OAuth credentials are provided through GitHub repository secrets and used by authorized workflows in runtime memory. The optional local authorization helper writes a credential file on the operator's own computer. Credentials are not intentionally included in generated artifacts or the progress branch. Protect repository administration and workflow-edit access, because authorized workflows can use configured secrets.

This repository and its workflow outputs are public. Generated audio/video inputs, lyrics, titles, descriptions, thumbnails, diagnostics and logs can be accessible through GitHub artifacts or branches. A private YouTube setting does not make the GitHub copy private. Do not use the public workflow for confidential content.

The progress branch stores source identifiers, YouTube channel/video/caption IDs and links, file hashes including subtitle hashes, run identifiers, queue order, upload and caption processing status and publication timestamps. Upload receipts contain similar information. Private-video IDs and unlisted links can therefore be public; unlisted links must not be treated as confidential.

Sharing and service providers

Google and YouTube receive authorized API requests and uploaded media. GitHub hosts the code, automation, secrets, artifacts and progress records. Google's OAuth Playground may process credentials during the optional browser-only authorization flow. Those services operate under their own policies, including the Google Privacy Policy and GitHub Privacy Statement.

The app does not sell or rent Google user data, use it for targeted advertising, or use Google-authorized account data to train general-purpose AI models. Local transcription and alignment are used to produce the owner's requested lyrics videos, not to train a new model. This static website adds no advertising, analytics scripts, forms or tracking cookies; hosting providers may process ordinary request logs.

Use and transfer of information received from Google APIs is limited to the disclosed publishing functions and is subject to the Google API Services User Data Policy, including applicable Limited Use requirements, and the YouTube API Services Developer Policies.

Retention

The current workflow requests two-day retention for input artifacts, three days for generated video kits, and fourteen days for upload-receipt artifacts. GitHub's repository settings and platform policies also apply. Logs and diagnostic branches have their own GitHub or operator-controlled retention.

Progress, uploaded-video identifiers and the verified-lyrics library remain in the state branch until the operator removes them. Git history can retain previous versions. This is not an automatic account-data deletion service: the operator must review and remove stored data as required by applicable Google/YouTube policies and deletion requests. Google grants and local credential files have separate operator-controlled lifetimes.

Revoke access and delete data

To stop future authorized access, remove this app from your Google account's third-party connections, disable publishing workflows, and delete the GitHub OAuth secret and any local credential files. Revocation alone does not delete existing YouTube uploads, artifacts or saved records.

The channel owner can delete videos in YouTube Studio. To remove GitHub copies, delete the relevant artifacts, logs and saved records through GitHub; old Git history, caches or provider backups may require additional provider-specific removal steps. Removing duplicate-protection records can allow a later replay to upload again, so stop publishing before cleanup.

For privacy questions, complaints or deletion requests, contact the operator at the support email shown on the Google consent screen. For non-sensitive issues, the project issue tracker is also available. Do not include tokens, credentials or confidential content in a public issue.

Changes

The operator must update this policy before changing the app's handling of Google user data and obtain any additional consent required by Google. Review the current policy and configured repository/workflow access before authorizing an installation.
